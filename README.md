# 🍎 Fruit Vision – זיהוי פירות בעזרת רשת נוירונים קונבולוציונית (CNN)

מערכת זיהוי תמונות מקצה לקצה: מאיסוף נתונים ואימון מודל ב-Google Colab ועד אתר שאפשר לפתוח בטלפון, לצלם פרי ולקבל את שמו ואת רמת הביטחון של המודל.

**5 קטגוריות:** תפוח (Apple), אבוקדו (Avocado), בננה (Banana), חציל (Eggplant), עגבנייה (Tomato).

| ממשק | הרצה | מתאים ל |
|---|---|---|
| **FastAPI** (אתר + REST API) | `uvicorn app.main:app` | שימוש בטלפון, חיבור לשירותים אחרים |
| **Streamlit** | `streamlit run streamlit_app.py` | הדגמה מהירה |

שני הממשקים משתמשים באותו מודול, [`app/predictor.py`](app/predictor.py), ולכן העיבוד המקדים והחיזוי זהים.

## תוצאות

הפרויקט עבר שלוש גרסאות. כל המספרים כאן **נמדדו על תמונות שהמודל לא ראה באימון**.

| גרסה | מודל | נבדק על | דיוק |
|---|---|---|---:|
| **v1** | CNN קטן (2 שכבות), Fruits-360 | סט הבדיקה של Fruits-360 (2,388, תמונות מעבדה) | **98.74%** |
| v1 | אותו מודל | 3,355 תמונות מעבדה מגוונות יותר (`Fruit_best/Test`) | 65.9% |
| **v2** | אותו CNN, אימון על `Fruit_best` (10.3 אלף תמונות אימון) | אותן 3,355 תמונות | **93.14%** |
| v2 | אותו מודל | 228 חיתוכי תמונות טלפון אמיתיות | **50.4%** |
| **v3** | MobileNetV2 (Transfer Learning) + החלפת רקע | `Fruit_v3/test` | _יעודכן אחרי האימון_ |

**מה למדתי מהמספרים:**

- דיוק גבוה על תמונות מעבדה לא אומר שהמודל יעבוד על תמונה מהטלפון. ב-v1 המודל קיבל 98.7% על נתוני המעבדה, אבל כשהתמונות גיוונו נפל ל-66%.
- ב-v1 הדיוק בוולידציה היה 100% כבר באפוק 2. הסיבה כנראה שתמונות רצופות של אותו פרי היו גם באימון וגם בוולידציה. אין להסיק מזה שהמודל מושלם. ב-v2 הוולידציה כבר חשפה התאמת יתר: 99.7% באימון ורק כ-77% בוולידציה.
- בבדיקה ידנית עם תמונות מהטלפון (תפוח ירוק ועגבנייה על משטח בית) אחד מה-CNN הקטנים שלפני v3 ענה "בננה" בביטחון 99.5% ו-99.9%, ואבוקדו זוהה כבננה ב-63.4%. נראה שהמודל הסתמך על הרקע ולא על הפרי.
- בגלל זה v3 שונה בשלושה דברים: נתונים מגוונים עם תמונות אמיתיות, החלפת רקעים בזמן האימון, ומודל מאומן מראש.

## איך המערכת עובדת

```
 תמונה (מצלמה / גלריה / קובץ)
          │
          ▼
 ┌──────────────────────────────┐
 │ app/predictor.py             │   הליבה המשותפת
 │  1. פתיחת התמונה + תיקון EXIF│   (טלפונים שומרים סיבוב כהערה)
 │  2. המרה ל-RGB               │
 │  3. שינוי גודל לקלט המודל    │   נלקח מהמודל עצמו (100 או 224)
 │  4. חלוקה ב-255 → ערכים 0..1 │
 │  5. מודל Keras → 5 הסתברויות │
 │  6. ביטחון < 60% → "unknown" │
 └──────────────────────────────┘
          │
          ▼
  {"prediction": "Banana", "confidence": 0.94, ...}
```

- **המודל נטען פעם אחת** בעליית השרת, ולא בכל בקשה.
- **גודל הקלט נלקח מהמודל**, לכן החלפת `models/model.keras` לא דורשת שינוי קוד.
- **סף `unknown`:** אם הביטחון נמוך מ-60%, התשובה היא `unknown`, אבל ההסתברויות המקוריות נשמרות.
- **אבטחה:** מקבלים רק JPG/PNG, עד 5MB. הקובץ נפתח באמת בעזרת Pillow, ולא סומכים על הסיומת.

## התקנה

> הפרויקט נבדק על **Python 3.12**. לא נבדקו גרסאות אחרות (על המחשב שלי הותקנה גם 3.14, ולא ניסיתי להתקין עליה TensorFlow).

```powershell
cd fruit-vision
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

אם PowerShell חוסם סקריפטים: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.
ב-VS Code: `Ctrl+Shift+P` ← **Python: Select Interpreter** ← בחר את `.venv`.

## גישה מהטלפון

### אותה רשת Wi-Fi
1. הרץ כך שהשרת יקשיב לכל הרשת:
   ```powershell
   uvicorn app.main:app --host 0.0.0.0 --port 8000
   ```
2. מצא את כתובת המחשב: `ipconfig` ← **IPv4 Address** (למשל `192.168.1.23`).
3. בטלפון פתח `http://192.168.1.23:8000`.
4. אם לא נטען: אשר ל-Python גישה ב-Windows Firewall, ברשת **פרטית**.

כפתור **"צילום תמונה"** באתר FastAPI פותח את המצלמה גם ב-HTTP. ב-Streamlit הרכיב `st.camera_input` **דורש HTTPS**, ולכן לצילום ב-Streamlit השתמש ב-ngrok.

### דרך האינטרנט עם ngrok (HTTPS)
1. התקן ngrok והירשם ב-https://ngrok.com. העתק את ה-authtoken.
2. חיבור חד-פעמי: `ngrok config add-authtoken <TOKEN>`. **הטוקן אישי, אל תעלה אותו ל-GitHub.**
3. הרץ את השרת, ובטרמינל נוסף: `ngrok http 8000` (או `ngrok http 8501` ל-Streamlit).
4. פתח בטלפון את הכתובת `https://xxxx.ngrok-free.app`.
5. **כבה את ngrok בסיום.** כל מי שיש לו את הקישור יכול להשתמש באפליקציה כשהוא פועל.

## API

`GET /health` ← `{"status":"ok","model_loaded":true,"classes":[...]}`

`POST /predict` (טופס `multipart`, שדה `file`, JPG/PNG עד 5MB):

```json
{
  "prediction": "Banana",
  "best_guess": "Banana",
  "confidence": 0.94,
  "is_unknown": false,
  "probabilities": {"Apple": 0.01, "Avocado": 0.02, "Banana": 0.94, "Eggplant": 0.01, "Tomato": 0.02}
}
```

כשהביטחון נמוך מ-**60%**, `prediction` הוא `"unknown"` ו-`is_unknown` הוא `true`. `best_guess` ו-`probabilities` נשארים כדי לראות לאן המודל נטה.

```powershell
curl -F "file=@tests/samples/Banana.jpg" http://localhost:8000/predict
```

קודי שגיאה: `415` סוג קובץ לא נתמך · `413` קובץ גדול מדי · `400` קובץ ריק או שאינו תמונה אמיתית.

## הנתונים

התיקייה [`data/Fruit_v3`](data/Fruit_v3) מכילה את כל התמונות שבהן אומן המודל: **7,831 לאימון ו-1,793 לבדיקה**. תיאור מלא ב-[`data/README.md`](data/README.md). בקצרה:

- **תמונות מעבדה** (Fruits-360): הרבה זנים, רקע לבן.
- **תמונות טלפון אמיתיות** (Fruits-360 `multi`): ארגזים, עצים ושווקים.
- **תמונות אינטרנט** (Wikimedia Commons, רישיון פתוח): נבחרו ידנית, וכל פרי נחתך בנפרד באמצעות סגמנטציה.
- **בדיקה על זנים שלא הופיעו באימון** ועל תמונות מקור שלא הופיעו באימון, כדי שהמדידה תהיה אמינה.

## אימון המודל (Colab)

| מחברת | מה היא עושה |
|---|---|
| `01_cnn_baseline_fruits360` | CNN קטן מאפס על Fruits-360 (v1) |
| `02_cnn_fruit_best` | אותו CNN על מערך גדול יותר (v2) |
| `03_transfer_learning_v3` | **MobileNetV2 + החלפת רקע** על `Fruit_v3` (v3) |

**להרצת v3:**
1. העלה את `data/Fruit_v3` כקובץ zip ל-Google Drive (`Fruit_v3.zip` עם תיקיית `Fruit_v3` בפנים), ועדכן את `ZIP_PATH` בתא 2.
2. ב-Colab: `Runtime ← Change runtime type ← GPU`, ואז `Runtime ← Run all`.
3. בסוף יורדים `model_v3.keras` ו-`class_names_v3.json`. שמור אותם כ-`models/model.keras` ו-`models/class_names.json`.

**מה v3 עושה אחרת:**

| שינוי | הסיבה |
|---|---|
| MobileNetV2 מאומן מראש (Transfer Learning) | כבר מכיר רקעים, תאורה ומרקמים מ-ImageNet |
| החלפת הרקע הלבן ברקעים אקראיים באימון | המודל מפסיק להסתמך על הרקע |
| ולידציה לפי קבוצות (זן / תמונת מקור) | תמונות כמעט זהות לא מופיעות גם באימון וגם בוולידציה |
| משקל x3 לתמונות אמיתיות ומשקל למחלקות | יש הרבה פחות תמונות אמיתיות |
| Label Smoothing, Dropout, Early Stopping | פחות ביטחון מופרז ופחות התאמת יתר |
| נרמול בתוך המודל | השרת ממשיך לשלוח ערכים בטווח 0..1 |

## מגבלות ידועות

- **המודל לא אומת על תמונות טלפון רגילות** בכמות משמעותית. ב-v2 ראינו כשלים מובהקים, ו-v3 נועד לשפר זאת. התוצאות יעודכנו אחרי האימון.
- **שגיאות בביטחון גבוה:** מודלים כאלה טועים לפעמים בביטחון של 90% ומעלה. סף ה-`unknown` ב-60% לא תופס אותן.
- **פרי אחד בתמונה:** המודל מסווג את התמונה כולה לקטגוריה אחת. הוא לא מזהה כמה פירות או פרי שאינו ברשימה.
- **5 קטגוריות בלבד.** פרי אחר יסווג לאחת מהחמש.
- **המודל שבמאגר:** הקובץ `models/model.keras` הוא המודל האחרון שאומן. יש להחליף אותו אחרי אימון v3.
